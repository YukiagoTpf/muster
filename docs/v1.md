# v1 scope

What v1 is, what it does, and what it deliberately does not.

## What v1 does

**Multi-platform config switcher & launcher** for coding agents — one Node.js codebase, zero dependencies, Node ≥ 20.

- **Profiles = whole-file snapshots.** A profile *is* a complete agent `settings.json`. Switching is a verbatim whole-file overwrite — no field merging, no managed-domain drift, and any present or future settings key works.
- **Two launch modes.** Sticky (`agentswap use` / `agentswap <name>`) sets the machine default and launches; per-launch (`agentswap run`) applies a profile through a private 0600 temp file, so N configs run side by side without touching global state.
- **Drift detection & conflict guards.** A three-way reconcile over live / profile / baseline hashes decides `in-sync` / `live-unsaved` / `profile-edited` / `conflict`; every entry point funnels through the same state machine, so CLI and web can't disagree. Unsaved live changes block a destructive switch until you choose (`--discard` / `--overwrite-profile`).
- **Transactional mutations.** A single cross-process lock (atomic `link(2)` create, stale-owner stealing with token re-read) is held across the whole read → reconcile → decide → write sequence; a switch journal recovers a crash mid-commit; all writes are tmp+rename with 0600 perms and win32 EPERM retry; live settings and each profile have independent rotated backup pools.
- **CLI with `--json` contracts everywhere** — `add / use / run / save / diff / show / rm / list / current / import / restore / backup / doctor / web / skill`, plus `agentswap <name>` quick-switch-and-launch.
- **Local web UI** (`agentswap web`) — stdlib HTTP server on loopback, per-session token in the URL fragment, Host/Origin guards, edits write straight to the profile files.
- **Agent skill** — teaches an agent to use AgentSwap and open herdr panes with a specific profile.
- **Safety** — secret masking in `show`/`diff`/list (`--reveal` opt-in), `run --json-cmd` emits env key *names* only, state is fingerprint-bound to one agent config dir, AgentSwap only ever *reads* the credentials file.

**Tested on** macOS (Node 24) and Linux (Node 22), 85 tests green. Windows is a cross-platform design with unit-test coverage.

## What v1 does NOT do

- **Windows real-machine verification.** The code is written cross-platform (config-dir resolution, `cmd.exe` shim wrapping, EPERM retry) and covered by unit tests, but it has not been run on a physical Windows box. Please open an issue if something misbehaves.
- **Field-level profile merging.** Profiles are whole-file snapshots by design; there is no partial override or shared-base + layer composition.
- **Settings semantics.** AgentSwap never parses or validates the *meaning* of settings content — any JSON object is a valid profile. It does not migrate settings between agent versions or warn about unknown keys. The web editor's structured tabs know key *names*, but only as a lossless projection over the canonical JSON, and only in the browser: nothing in the store, reconcile, sync or CLI layers reads a settings key. See [architecture.md](architecture.md#the-structured-editor-is-a-projection-not-a-parser).
- **A background daemon.** AgentSwap is a CLI plus an on-demand web server; nothing runs persistently in the background. Multi-machine sync (0.4.0) is still on-demand SSH, not a daemon.

## Resolved after v1

- **Multi-machine sync (0.4.0).** v1 was single-machine: one `AGENTSWAP_HOME`, no network. 0.4.0 adds SSH push/pull/sync between machines that already run AgentSwap — still no cloud, no account, no listening port. Design: [docs/sync.md](sync.md).

## Known limitations

- The cross-process lock is a zero-dependency userspace lock (a lock file with `pid:token`). It closes every same-process race and every cross-process race except one irreducible window (two thieves racing one dead lock between a re-read and a rename — two adjacent syscalls). That window is bounded by write-time and end-of-transaction fencing plus journal/reconcile recovery, not by an OS lock (`flock`/`LockFileEx` aren't in Node's stdlib). A lock from an incompatible AgentSwap generation is left untouched and fails closed (`ELOCKFORMAT`) rather than being stolen.
- A live process that can never release its lock (e.g. a wedged holder) blocks contenders until the process exits — there is no lease-based theft of a live-pid lock. This is deliberate: a minutes-old lock is more likely a fault than a live holder, and failing closed beats stealing a lock a live owner still holds.
